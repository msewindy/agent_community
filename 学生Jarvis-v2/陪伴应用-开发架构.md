# 陪伴应用 · 开发架构

> **日期**：2026-10-18  
> **效力**：指导新框架的第一期实现。不重定义 [L0 能力契约](./L0-能力契约/Jarvis能力契约.md)。学习场景的业务规则仍以 [L1](./L1-场景域/02-平台架构设计与实现说明.md) 为准。  
> **硬件**：只使用 Reachy Mini Wireless（树莓派 CM4）。大模型走云端。  
> **本期默认**（未另行拍板前按此实现）：语音为「听写 → Hermes → 朗读」；Hermes 常驻在陪伴应用内；屏幕是机器人提供的网页；第一期不接打印机。

---

## 1. 已定决策

| ID | 决策 |
|----|------|
| D1 | 机器人是唯一主机。不另外部署家庭 Alpha 那台电脑作为大脑。 |
| D2 | 一个产品、一个大脑、一个身体。学生 Jarvis 是第一个场景插件，不是并行的第二套系统。 |
| D3 | 大脑是 Hermes。官方 Conversation 里的 Hugging Face 实时大模型不再当大脑。 |
| D4 | 身体是 Reachy daemon，加上 Conversation 里属于身体的能力：音频流、麦克风板调参、转头、跟人脸、舞蹈、表情、说话时头晃、音量、睡眠、空闲小动作、音色、听写语言。 |
| D5 | 陪伴记忆（称呼、习惯、关系）与学情（掌握、错题）分开存储。 |
| D6 | Hermes 在陪伴应用启动时加载一次。一轮对话不得再创建 `hermes chat` 进程。 |
| D7 | 模型按句输出。第一句开始朗读时，整段回复可以尚未结束。 |
| D8 | 慢动作（看图、打印、入库）不挡住已经开始的那句话。 |

现有实现与 D6 的差距：`agent_platform/voice/hermes_bridge.py` 每一轮都 `Popen` 一次 `hermes chat`。这就是试用文档里「首轮冷启动 + 首包易超过 60 秒」的来源（见 L1《平台架构》§9、《封版内容与残留问题》、《试用观察表》）。新代码不得再走这条路径。

## 3. 进程与启动

开机后只有这些常驻进程：

| 顺序 | 进程 | 谁拉起 | 挂了以后 |
|------|------|--------|----------|
| 1 | mihomo | systemd `mihomo.service` | systemd 重启。只听 `127.0.0.1:7897` |
| 2 | reachy-mini-daemon | systemd，`launcher.sh` 里 `--wireless-version --no-wake-up-on-start` | systemd 重启。机器人保持睡眠，直到被唤醒 |
| 3 | 陪伴应用 | daemon 的 `startup_app`，在**第一次唤醒**时启动（含摸天线） | daemon 按应用停止处理。不在睡眠期间空转大模型 |
| 4 | Hermes 运行时 | 陪伴应用进程内的常驻会话，随应用启动加载插件 | 应用重启时一起重启。一轮话结束不退出 |

守护应用的环境变量继续由 daemon 继承：`HTTP_PROXY` / `HTTPS_PROXY` 指向 `http://127.0.0.1:7897`，`NO_PROXY` 含 `localhost,127.0.0.1,reachy-mini.local`。

官方行为：Wireless 上电后 daemon 先起来，机器人是睡的。`startup_app` 在第一次唤醒时启动，不是在电源按下的那一秒。见 [Building & Publishing Apps](https://huggingface.co/docs/reachy_mini/SDK/apps) 中 “Make an app start on wake-up or antenna touch”。

## 5. 模块

```text
companion/
  app.py                 ReachyMiniApp 入口，交给 daemon
  session.py             一轮话：听写 → Hermes → 分句朗读 / 上屏
  hermes_runtime.py      常驻 Hermes。启动时加载插件，之后只接收一轮文本
  body/                  对 daemon 的动作与音频封装
  scenes/learning.py     第一个场景：把 learning 工具注册进 Hermes
  web/                   屏幕页面与上传入口（上传第一期只留路由）
  data/                  本机 SQLite 的打开与路径
```

`body/` 要包住的官方能力：

| 能力 | 来源 |
|------|------|
| 麦克风 / 扬声器流 | Conversation `streaming.py` |
| 麦克风板降噪与回声消除 | `audio/startup_config.py` |
| 转头、扫视、跟人脸、舞蹈、表情、说话时头晃 | `moves.py` 与对应 tools |
| 音量 | `tools/volume_control.py` |
| 睡眠与空闲计时 | `go_to_sleep`、空闲超时线程 |
| 音色 | `startup_settings` 的 voice。朗读引擎换成自有 TTS 后，仍保存「当前声音」 |
| 听写语言 | `language`，第一期固定可用 `zh` |

人格提示词、`memory.v1.json`、Hugging Face 实时会话、天气/搜索类 MCP，不进入 `body/`。

## 6. 三套接口

### 6.1 Hermes 常驻会话

陪伴应用只依赖这个接口，不依赖 `hermes chat` 命令行：

```text
start() -> ready          进程启动时调用一次
turn(text, context) -> stream of text chunks
cancel()
shutdown()
```

`context` 只放本轮需要的短背景（当前场景、音色无关的学情一句话）。跨会话事实由 Hermes 记忆自己读，不在这里重塞一份。

第一期适配：若当前 Hermes 只有 CLI，就在 `start()` 里拉起**一个**长寿命进程并保持到 `shutdown()`。禁止在 `turn()` 里 `Popen`。插件加载必须发生在 `start()`。

### 6.2 身体动作

场景和 Hermes 不直接碰电机。只调用：

```text
speak(text)               朗读，可被下一句打断
move_head(direction)
look_at_face(on)
play_emotion(name)
play_dance(name)
set_volume(target, level)
sleep()
capture_frame() -> image  第一期可实现，不接到拍作业流程
```

`speak` 由会话循环调用，不做成让模型自己决定的工具，避免一句话被工具调用打断才出声。

### 6.3 场景插件

一个场景提供：

```text
id
system_hint          加进本轮系统提示的短文本
tools                Hermes 可调用的函数列表
on_boot()            应用启动时注册一次
```

学习场景第一期只注册三个工具，对应现有实现：

| 工具 | 现有代码 |
|------|----------|
| 讲解一个知识点 | `explain_kp` |
| 出一道题 | `questions_suggest` + `question_get` |
| 交卷 | `attempt_submit` |

学情读写仍用 `agent_platform/learning/`。工具内部不得启动新的 Hermes。

以后的故事、习惯、阅读，是新的场景插件，走同一套三个接口。

## 7. 一轮话的时序

```text
唤醒（已完成，应用已在跑，Hermes 已 ready）
  → 麦克风一句结束
  → 听写（云端）
  → hermes_runtime.turn()          此处不得出现新进程
  → 收到第一句
       → speak() 开始
       → 屏幕显示同一句
  → 若本轮要出题或交卷：工具写 SQLite，结果再进入后续句子
  → 本轮结束，Hermes 进程仍在
```

验收：

1. 应用启动日志里 Hermes 加载插件出现一次。第二轮及以后的日志里没有新的 `hermes chat` 进程。
2. 第一句已经在播放时，允许后面的句子还在生成。
3. 出题或交卷失败时，嘴上先有一句说明，不把整轮卡死到超时。

不把「首字小于 N 秒」写成承诺。试用里要消掉的是文档中的整轮冷启动（首轮易超过 60 秒），不是模型本身的网络时间。

学情结论不写入陪伴记忆。Conversation 现有的 `memory.v1.json` 不迁移进新记忆，避免把聊天事实当成学情。

## 10. 部署注意

- 应用装进 `/venvs/apps_venv`，`startup_app` 保持为这一个陪伴应用。官方 Conversation 不再作为开机应用。
- CM4 内存 4GB。常驻的是 daemon、mihomo、陪伴应用和其中的 Hermes。不要再加 MemVerse 容器。
- 磁盘约 16GB 且已经较满。题库用 SQLite 一份，不把家庭 Alpha 的整棵数据目录拷上机器人。
- 云端密钥放在 `/home/pollen/.config/companion/env`，由陪伴应用读取，不写进仓库。
