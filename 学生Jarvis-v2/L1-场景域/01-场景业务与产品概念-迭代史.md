## R6 · 2026-07-19：第一性原理复盘（最新）

### R6.1 为何再开一轮

试用中出现：孩子对话里「听了课、做了题」，家长页仍显示「尚未开始」。共识是——**不能再单点打补丁**，须先把教育过程对象说清，再定 Agent 功能。

### R6.2 业务分析结论（过程四问）

有效家庭学习必须同时回答：

1. **学什么**——内容边界（教材、年级）  
2. **怎么学**——听讲、练习、订正、复习如何展开  
3. **学得怎样**——进度与掌握如何被看见、纠正  
4. **谁负责什么**——学生 / 家长 / 教研权责  

教育 Agent **不是**这四个问题本身，而是让过程更顺畅发生的智能角色。

### R6.3 产品概念（建议模型 · 在已有提炼上完善）

**采纳的骨架**：学生、家长、教研、单元、知识点、习题、教案/讲解材料、学情。

**三处补强（否则过程会断）**：

| 补强 | 内容 |
|------|------|
| 学情拆分 | **学习进度**（做过什么）≠ **掌握学情**（会不会，须证据） |
| 学习活动 | 听讲/练习等事件账本；无此则「今天学了什么」只能靠聊天回忆 |
| 内容三件套 | 知识点=学什么；教案=怎么教；习题=会不会——分开演进 |

**四层结构**：

| 层 | 对象 |
|----|------|
| 角色 | 学生、画像、家长、老师/教研 |
| 内容 | 单元、知识点、习题、讲解点/详细教案、课堂活动 |
| 过程 | 学习情境、学习活动、作答记录、掌握判断 |
| 呈现 | 学生任务/鼓励；家长「进度块 + 掌握块」 |

### R6.4 目标业务过程（A–E）

| 过程 | 要点 |
|------|------|
| A 内容建设 | 教材→KP / 习题 / 课堂活动三分流 → 人审生效 |
| B 学新知 | 对齐情境 → 按教案讲 → 记听讲活动 → **不**自动「已掌握」 |
| C 练习检验 | 选题→作答→作答记录→更新掌握→记练习活动；无题诚实降级 |
| D 真实作业 | 讲解 或 记入学情；低把握→待确认 |
| E 家长治理 | 看进度、看掌握+证据、订正、补内容 |

### R6.5 功能需求（从模型抽象的 Agent 能力 F1–F6）

| 功能 | 职责 |
|------|------|
| **F1 情境对齐** | 学科/单元/年级边界 |
| **F2 教学讲解** | 取教案、分步讲、记听讲活动 |
| **F3 练习与检验** | 出题—作答—落库—更新掌握（禁止口头闭环） |
| **F4 真实任务接入** | 拍照作业进入同一套对象 |
| **F5 进度与掌握陈述** | 亲子看到同一事实；掌握须有证据 |
| **F6 陪伴与安全** | 适龄语气、拒答、可拉回学习主线 |

**Agent 定位**：过程调度者 + 适龄讲解者；**不是**内容权威，也不是可随意宣布「已掌握」的成绩单。

### R6.6 本轮待拍板（研讨用）

1. 是否正式采纳「进度 / 掌握」二分？  
2. 「学习活动」是否作为一等对象？  
3. 无题库时自编题能否影响掌握？  
4. 详细教案 vs 讲解点：一物加深还是两套？  
5. KP 变更是否一律人审？  
6. Agent 偏「调度+讲解」还是「高强度替代家教」？  
7. 学情数据默认家庭本地主权？

### R6.7 对外研讨载体

无技术术语的完整论述见归档：`history/教育Agent产品分析-研讨稿.html`（浏览器打开 / 打印 PDF）。

## R5 · 2026-07-15～16：试用后路线与版本切片

### R5.1 业务判断

试用已启动 → 目标从「能通」转为「敢长期用」。优先级按**试用反馈风险**，不按工程兴趣。

### R5.2 功能需求排序（重要 × 成本）

| 优先级 | 需求 | 落入版本设想 |
|--------|------|----------------|
| P0 | 试用观察 + 主攻单元内容加深 | v1.0 |
| P1 | 家长学情订正 + 周报证据链 | v1.0 |
| P1 | 家长 PDF Web 入库（T1） | v1.2 |
| P2 | 微计划 + 孩子鼓励视图；流式体验 | v1.1 |
| P3 | 对话式录入、内容包、PWA | v2.0 |
| 暂缓 | 多模态课本题推题、公网多租户、原生 App | — |

### R5.3 产品概念：可部署版本阶梯

```text
v0.9 家庭 Alpha（当前封版）→ v1.0 可信学情 → v1.1 日练陪伴
  → v1.2 家长产能 → v2.0 家庭终端
```

原则：每一阶段发布后是**可独立部署、可独立试用一周**的完整版本。

### R5.4 服务形态概念（非实现承诺）

- **私密数据**（学情、对话、照片）默认家庭本地  
- **公共内容**（KP/题/Wiki）可做成可下载内容包  
- 终端：先 Web，再 PWA；不急原生双端  

详情见归档：`history/试用后-遗留问题与下一步推进.md` · `history/分阶段版本计划.md`。

## R3 · 2026-06-23～24：功能架构与学情主轴定稿

### R3.1 三大架构决策（仍有效）

| 决策 | 内容 |
|------|------|
| **D1** | 学情主轴 = **知识点**（不再以错因码为进学情闸门） |
| **D2** | 知识点由家长/教师经 KP 文档确认（权威源） |
| **D3** | 错题归类自动做；家长可查看/修改/纠正 |

### R3.2 设计原则（AP1–AP6）

对话主线程 · 知识点坐标系 · 权威与自动分离 · 证据优先（仅约束场景结论） · 能力分层可选 · 学情与 M2 画像双轨不互染。

### R3.3 功能需求：S-A→S-D（已关闭）

拍照理解 → Agent 意图编排 → 归类分流 → 学情/inbox → 家长处理——产品主线打通。

### R3.4 业务编排概念（P7）

本域**不规定固定流程**，只提供数据组件 + 业务操作，由 Agent 按意图编排。典型分流：

| 意图 | 应走 | 禁止 |
|------|------|------|
| 讲新课 | 讲解（Wiki/KP） | 默认出题、peek 离线队列 |
| 练题 | `questions_suggest`→作答→`attempt_submit` | 口头闭环（R6 强化） |
| 拍照记错 | `classify_photo` | 「一拍照必入库」状态机 |

2026-06-24 纠偏：`push_queue` 降为微计划缓存，**不是**默认练题入口。

归档：`history/功能架构-模块与数据流.md`。

## R2 · 2026-06-20～22：切片验证形成的业务基线

| 切片主题 | 业务/功能结论 |
|----------|----------------|
| 自然对话 | 学伴语气、共情、跨会话记忆成立 |
| 学习闭环融入 | 做题→gap→推题可落库；不破坏学伴感 |
| 真实作业答疑 | 离库题可答疑；随后 freeform 可入学情 |
| Web 孩子入口 | 浏览器聊天替代 CLI；逻辑复用 Agent |

此轮确立：**对话是主线程，学习管线是工具**——后续轮次均不得回退。

归档：`history/小学学习域.md` §0.1–0.5。

## R1 · 2026-06-20：L1 挂载框架（起点）

### R1.1 场景定位（一句话）

> 小学学习 = 在 Jarvis 通用能力之上，**注入教育背景 + 挂载学习工具 + 施加年级与安全边界**。

### R1.2 与 L0 的边界

- **不做**：重定义对话/记忆/主动/校准/进化  
- **只做**：I1 注入、I2 工具、I3 边界、I4 场景画像信号  

### R1.3 初始产品概念

学习场景是挂载，不是「学习机换皮」；换场景不应推翻 L0。

归档：`history/小学学习域.md` 文首与修订 2026-06-20。

## 附录 · 概念词典（跨轮次统一用语）

| 用语 | 现行含义（R6） | 易混淆点 |
|------|----------------|----------|
| 学习情境 Focus | 当前对齐的学科/单元 | ≠ 已掌握 |
| 学习进度 | 听了/练了什么（活动+次数） | ≠ 掌握学情 |
| 掌握学情 | KP 上的掌握判断 + 证据 | 须 attempt 或家长订正 |
| 知识点 KP | 可判断会不会的最小原子 | 权威由人确认 |
| 习题 | 检验用题目 | 与课堂活动分开 |
| 教案/讲解点 | 怎么教 | 浅/深两档，勿假装已有完整教案体系 |
| 学习活动 | 过程事件账本 | R6 建议新增；封版尚未产品化 |
| 教育 Agent | 过程调度 + 讲解 | 非内容权威 |
