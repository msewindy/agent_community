## 2. 学习 Jarvis 产品下一步推进建议

前提：**试用已启动** → 下一阶段目标应从「能通」切到「**敢长期用、愿意天天用**」。优先级建议按「试用反馈风险」排，而不是按工程兴趣排。

### 2.1 功能完善（建议四波，约 4–8 周视角）

**Wave A · 试用护栏（立刻）**

- 稳定：启动、Key、语音按住说话、框架话泄露、超纲拦截——已基本具备，改为 **每周收集试用日志** 闭环修。  
- 内容：优先把试用家庭主攻单元 Wiki / 题量补到「能讲 10 分钟、能练 20 分钟」的可用深度（比再开多模态题型更赚钱）。  

**Wave B · 家长侧闭环（文档 #1/#2，最该做）**

试用里家长最容易流失的点是：「我怎么知道这周学明白没有？错了能不能改？证据在哪？」  
应优先做：

1. gap **手动订正** + 操作留痕（provenance）  
2. 周报可点进 attempt / 照片证据  
3.（轻量）中置信「待确认」一条列表，降低 inbox 过载感  

**Wave C · 孩子侧「感觉有进步」（#3/#4）**

微计划「今天练 20 分钟」、练完出现「本周攻下了 X」鼓励视图——否则孩子觉得只是「会说话的卷子」。  

**Wave D · 录入产能（T1 先于 T2）**

家长若完全靠工程师跑 CLI，试用扩展会卡死。

- 先做 **T1：PDF 一键入库**（复用现有三分流）  
- **T2 对话式录入** 放后（编排复杂，且有 3 个决策留白）  

多模态题型（问题4）**不建议作为试用下一阶段主线**；继续用「课堂活动清单 + 纯文本题」即可。

### 2.2 使用体验（试用中马上会被吐槽的）

| 用户痛点 | 现状 | 建议 |
|----------|------|------|
| 等半分钟才回 | Alpha 已说明；有「在想…」 | 真流式 SSE、分段首 token；或提示「预计 15–30 秒」 |
| 语音不稳 / 交互怪 | 刚改成按住说话 | 试用机强制硬刷新 + 验收脚本；失败回退文案要更清晰 |
| 讲新课空洞 | Wiki 骨架 | 主攻单元人工补教案 3–5 篇优先于扩单元 |
| 拍照总进 inbox | 归类保守 | 家长一键确认 UX；阈值调参基于纠错率 |
| 平板局域网难开 | P2 已知 | **局域网部署一页纸 + 固定主机名 / 二维码** |
| 「不知道今天干嘛」 | 微计划未产品化 | Welcome 一条今日微计划入口 |

### 2.3 模拟角色看法

**学生（三年级）**

- 喜欢：能说话、会鼓励、拍照少打字。  
- 不爽：干等、重复「再对齐一下」、讲得像说明书。  
- 会要：今日目标（3 道题 / 讲一个知识点）、讲完有小星星或「你攻下了…」。  

**家长**

- 喜欢：不用每晚盯着刷题 APP。  
- 不爽：8770「看不懂」、inbox 堆积、改不了误判、不知「这周到底行不行」。  
- 会要：**每周 3 分钟周报**（进步 3 条 + 待处理 1 条 + 可订正）；PDF 丢进去就能变知识点。  

**老师（若有）**

- 关心：是否干扰课堂教参、KP 是否权威、能否批导入。  
- 现阶段更像「家庭学伴」而非「班级 LMS」——**别抢老师批改与班级排课**，做家庭补位更顺。  

### 2.4 产品服务方式（建议形态）

不建议一上来做公网多租户 SaaS（文档也明确不承诺）。更贴合现状的是：

```text
┌─ 家庭私有运行时（本机 / NAS / 小主机）─────────────┐
│  孩子端 App 或 PWA（先 Web，后可包壳）               │
│  家长端 Web / 同 App 家长模式                        │
│  私密数据本地：student_data / memory / 对话 / 照片   │
│  推理可走云 API（DeepSeek / 百炼）— 密钥家长自持     │
└────────────────────────────────────────────────────┘
         │ 可选同步（只下公共资源）
         ▼
┌─ 内容云（只读 / 签名包）───────────────────────────┐
│  KP catalog、题库 seed、Wiki 讲解包、教材解析模板   │
│  版本化下载（按年级·教材·学期），不含孩子学情     │
└────────────────────────────────────────────────────┘
```

| 层 | 建议 |
|----|------|
| **终端** | 试用继续 Web（8771/8770）；下一形态 **PWA / 平板壳**，不必先做原生双端 App。手机可做「家长通知轻入口」。 |
| **私密数据** | **本地权威**：学情、记忆、照片、对话。云端仅作可选备份（端到端加密）。 |
| **公共数据** | KP / 题 / Wiki / 解析器做成 **可下载内容包**（与学生隔离）；家庭可离线练已下内容。 |
| **算力** | 大模型与 ASR / VLM **继续云 API**（成本低、装机简单）；本地仅边缘（后续可选）。 |
| **账号** | 试用单孩绑定主机；多孩切换是后续产品，不堵 Wave B。 |
| **收费** | 可能路径：内容包订阅 + API 用量自持；或「软硬件一体的家庭学习主机」。 |

核心原则：**学情不出家门，教案可以出云端。**

## 3. 一句话结论

文档遗留的**真·产品债**是：家长还不能完全「自己管学情、自己扩内容」；孩子端还缺「今天干完了 / 我进步了」的反馈环。试用期应 **内容加深 + 家长治理闭环** 双轨并行，同时用观察数据决定是否立刻做流式 / PDF Web；**服务形态走「家庭本地私密数据 + 云公共内容包 + Web/PWA 终端」**，比重做多模态题型或公网 SaaS 更贴当前真实阶段。
