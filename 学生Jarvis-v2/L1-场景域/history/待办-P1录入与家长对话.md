### T5 · 孩子做题未落入学情（口头出题绕过工具链）— 2026-07-19 试用复盘

> **优先级**：P0（信任事故：孩子以为「考过了」，家长页显示「未开始」）  
> **性质**：Agent 编排合规缺口 + 内容缺口，**不是**家长页读写 bug。  
> **工程状态（2026-07-23）**：✅ 提示词硬规则 + 空库 `agent_instruction` + pre_llm 题库数量注入已合入；语文 u01 已补 12 题。T5-4（试用抽样占比）靠观察表跟踪。

#### 现象

试用当天学生在 8771：

1. 学英语 / 数学 / 语文第一单元（听讲 + 明确要求「出几道题考考我」）；
2. 口头作答多轮（如选项 `1A2B…`、数学「第一题是七…」、应用题答案等）；
3. 刷新 8770 学情总览 → 三科 `attempts_total=0`、无今日记录。

#### 证据（只读排查）

| 检查项 | 结果 |
|--------|------|
| `student_data/g2-stu-01/attempts/` | **不存在**；无 `att-*.json` |
| `context.json` | 已切到语文 `chinese-g3-u01`（讲新课预检会 `set_learning_focus`）；`session_stats: null` |
| Hermes `agent.log` 当日会话 | 多轮用户做题/答题；**每一轮 `tool_turns=0`** |
| 当日 `tool_executor` | **未出现** `questions_suggest` / `question_get` / `attempt_submit` 完成记录 |
| 语文 `chinese-g3-u01` 题库 | `questions_suggest` 返回 **0 题**（加重「模型自编题」） |

#### 根因

1. **主因**：提示词要求练题走 `questions_suggest → question_get → attempt_submit`，模型却**纯文本出题并口头判分**，学情管道被绕开。  
2. **加重**：部分单元（尤其语文）可判分题不足 / 为 0，工具链即使调用也易空，进一步诱导自编题。  
3. **易混淆**：讲新课预检会改 `context`（学习情境），家长页却只展示 attempt/gap，造成「学了但学情为空」的观感。

#### 目标修复方向（待排期；勿只改家长 UI）

| 方向 | 说明 |
|------|------|
| **强制落库** | 检测到「考考我 / 出题 / 答题」意图时，禁止纯口头闭环；有题库 → 必须 `attempt_submit`；无题号真题 → `attempt_submit_freeform` |
| **空题库策略** | suggest 返回 0 题时：诚实说明「这单元还没有练习题」，引导换单元 / 拍照 / 家长补题；**禁止**假装题库考完 |
| **可观测** | 日志或开发面板暴露本轮是否调用了 attempt 工具；试用观察表加「做题未落库」项 |
| **产品层（另文）** | 「听讲进度 / 今日活动」应纳入广义学情，见 [领域概念与业务过程复盘](./领域概念与业务过程复盘.md)；与本 T5「作答必须落库」分开做 |

#### 验收口径（T5 关闭时）

| # | 标准 |
|---|------|
| T5-1 | 孩子说「出几道数学第一单元题」→ 日志出现 `questions_suggest` + `question_get`；答完出现 `attempt_submit` 且磁盘有 `att-*.json` |
| T5-2 | 8770 learning-dashboard 对应学科 `attempts_total ≥ 1`，刷新可见 |
