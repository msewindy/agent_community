出发点：学习何以发生

无论是否使用人工智能，一次有效的家庭学习，至少要同时回答四个问题：

  1. 学什么——内容的边界是什么（相对教材、年级是否站得住）？
  2. 怎么学——听讲、练习、订正、复习，过程如何展开？
  3. 学得怎样——进度与掌握如何被看见、如何被纠正？
  4. 谁负责什么——学生、家长、老师（教研）各自的权责？

教育 Agent 不是这四个问题本身，而是帮助上述过程更顺畅发生的智能角色。若过程模型不清楚，Agent 功能必然漂移：有时像闲聊伙伴，有时像题库机器，有时像成绩单——却无法稳定地「伴学」。

第一性原理：先为「学习」建模，再为「助手」列功能。助手的能力必须能映射回过程中的某一步；映射不上的，不做或单列讨论。

第一部分 · 教育过程建模

1.1 我们采纳的建模立场

在已有讨论中，已经提炼出一组核心对象：学生、家长、知识点、习题、教案（讲解材料）、学情 等。我们认为这一组对象方向正确、可以成为正式模型的骨架，同时需要做三处补强，否则过程会断、概念会糊：

  1. 把笼统的「学情」拆成学习进度与掌握判断（见 1.4）；
  2. 补上学习活动作为过程足迹（听讲、练习、订正等事件）；
  3. 明确单元与课堂活动在内容层的位置（教材结构与「不宜自动判分」的活动）。
下文凡称「建议模型」，即指：在你们已提炼概念上完善后的模型。若讨论中要改名，可以改；但同一体系内每个词只能有一个含义。

1.2 四层结构

角色层
谁在学、谁监护、谁定义内容权威
内容层
学什么、用什么练、用什么教（相对稳定，权威可审）
过程层
这一次如何学：情境、活动、作答、掌握变化（动态，属学生）
呈现层
不同角色看到什么视图（学生的鼓励与任务，家长的进度与掌握）

1.3 概念定义（充分论述）

角色层

学生
学习的主体；一切进度与掌握结论的归属人。

没有「学生」这一锚点，内容再丰富也只是教材库，不是学习产品。多孩家庭可以有多个学生实体，但每个实体的过程数据相互隔离。

学生画像
关于「这个人」的稳定信息：年级、称呼、偏好、沟通习惯等。

画像服务「如何对待这个人」，不服务「某知识点会不会」。二者必须分开，否则容易用印象代替证据。

家长（监护者）
对学习结果负监护责任的人：看见、纠偏、必要时补充内容。

家庭场景里，家长不是「第二个学生」，而是权威与信任的出口。系统自动结论必须可被家长理解与订正。

老师 / 教研
内容权威的定义者或审核者：知识点是否成立、是否贴合教材与年级。

在纯家庭试用中，家长可暂代教研角色；模型上仍应保留「内容权威 ≠ 学习主体」。

内容层：学什么、怎么教、怎么验

单元
教材中的教学段落（册、单元、主题），是「对齐当前学什么」的常用粒度。

孩子说「学第一单元」时，对齐的是单元，而不是立刻落到某一个细知识点。单元包含若干知识点，也可关联课堂活动。

知识点
可单独讨论「会或不会」的最小课程原子；掌握判断的坐标系。

没有知识点，就只能说「数学不太好」，无法说「两步运算的乘加还不稳」。知识点应由人权威确认，不宜由对话随口生成并当作事实。

习题
用于检验「会不会」的题目；理想情况下可判分或可按约定规则评判。

习题回答的是验证问题，不回答教学内容结构问题。有知识点无习题，仍可讲解；有习题无知识点，则练习无法沉淀为掌握结论。

教案 / 讲解材料
回答「怎么教」：目标、例示、步骤、关键提醒；可以有深浅两档。

讲解点（浅）：够支撑一次分步讲解的要点。
详细教案（深）：含目标、例题序列、活动设计、易错预设等，供更高质量教学。
二者都挂在知识点（或单元）上，但深度不同；缺详细教案时，仍可用讲解点教学，而不应假装「已经有完整教案体系」。

课堂活动
教材中依赖听、说、演、做，且不宜纳入自动刷题闭环的活动。

强行改成「伪选择题」会伤害教学真实性。它们可以出现在进度（做过/引导过），但默认不进入「自动判分→掌握」主链。

内容三件套：知识点定义「学什么」，教案定义「怎么教」，习题定义「会不会」。三者分开演进——缺一不阻碍另外两者存在，但完整伴学需要三者逐渐齐备。

过程层：这一次学习如何留下痕迹

学习情境
当前对话对齐的学科 / 单元（有时具体到知识点）。

情境保证「下一句讲解或出题」不跑题。情境切换是过程事件，本身不等于掌握。

学习活动
一次可记录的学习事件：听讲、练习、订正讲解、拍照讨论等。

没有活动账本，「今天学了什么」只能靠聊天回忆，家长与学生无法共享同一事实。活动记录进度，不自动等于掌握。

作答记录
一次可追溯的答题事实：题是什么、答了什么、对错如何判定。

掌握判断若要可信，必须能回到作答。口头说「你答对了」却不留记录，不是学习过程的完整闭环。

掌握判断
针对某知识点的结论状态（如未练、薄弱、稳定掌握等），由作答累积，并可被家长订正。

这是「学情」一词最容易被误用的部分。它必须可解释、可纠正，否则监护者无法信任。

1.4 「学情」一词的拆分（建模关键）

口语中的「学情」过于宽泛。建议在产品与教研语言中固定为两套可见对象：

用语 含义 主要依据 能否直接说「学会了」
学习进度 一段时间内听了什么、练了什么、覆盖到哪些单元/知识点 学习活动 + 作答次数等 不能。进度描述「做过」，不描述「会了」
掌握学情 某知识点当前的掌握判断，及支撑它的证据 作答记录，及家长订正 可以，但必须带证据或人工确认

另有一类对人的了解（称呼、情绪、习惯），属于陪伴质量，不属于掌握学情。三者并存，互不替代。

1.5 对象如何关联

  • 一个单元包含多个知识点，可关联若干课堂活动。
  • 一个知识点可挂接讲解材料 / 教案，并可挂接多道习题。
  • 学生在某一时刻处于某个学习情境（通常指向单元）。
  • 学生的一次听讲或练习，产生学习活动；若包含答题，再产生作答记录。
  • 掌握判断挂在「学生 × 知识点」上，由作答沉淀，可被家长修改。
关系纪律：内容层对象描述世界「应该学什么」；过程层对象描述「这个学生实际发生了什么」。Agent 可以说话，但不能用一句话同时冒充两种对象。

1.6 正确的业务过程（目标态）

下列过程是「教育应该如何发生」的描述，不依赖任何具体软件形态。

过程 A · 内容建设（教研 / 家长代行）
  1. 从教材或资料识别单元与知识点；
  2. 为知识点准备讲解材料（由浅到深）；
  3. 为需要检验的知识点准备习题；
  4. 将不宜自动检验的部分标为课堂活动；
  5. 经权威确认后，成为可教、可练的内容基线。
过程 B · 学新知（学生）
  1. 明确学习情境（学哪一单元 / 主题）；
  2. 依据讲解材料进行教学（分步、举例、追问）；
  3. 记下一次「听讲」类学习活动；
  4. 不因「听过」自动写入「已掌握」。
过程 C · 练习与检验（学生）
  1. 在当前情境下选取合适习题；
  2. 学生作答；
  3. 形成作答记录（对错与依据）；
  4. 更新对应知识点的掌握判断；
  5. 记下一次「练习」类学习活动；
  6. 若无可用习题：诚实说明，并导向替代路径（换内容、真实作业、人工补题），而不是用无法追溯的口头考试代替。
过程 D · 真实作业进入过程（学生 / 家长）
  1. 呈现一道真实题目（如拍照）；
  2. 分支一：只要讲解 → 教学 + 活动记录；
  3. 分支二：要记入掌握 → 尽量挂到知识点；不确定则进入「待确认」，由家长裁定；
  4. 确认后的结果与过程 C 一样，进入作答与掌握。
过程 E · 监护与治理（家长）
  1. 查看学习进度（活动与覆盖）；
  2. 查看掌握学情（结论 + 证据）；
  3. 订正误判，并保留「谁改了什么」；
  4. 在需要时补充知识点、习题或讲解材料（回到过程 A）。

1.7 建模小结

建议用一句话记住整个模型：

学生是主体；知识点、习题、教案是内容；学习活动是足迹；作答与掌握判断是证据；家长是监护与纠偏；老师/教研是内容权威。

第二部分 · 从模型到教育 Agent 功能

Agent 的价值，是让第一部分中的过程 B–E 在对话中自然发生，且不破坏对象纪律。下面的功能是从模型抽象出来的能力清单，而不是某一版软件菜单的说明书。

2.1 Agent 的角色定义

教育 Agent = 学习过程的对话式调度者 + 适龄讲解者。

它是

  • 意图理解者：判断此刻要学、要练、要问、要看作业还是只要陪伴
  • 过程执行者：推动情境对齐、取讲解、取题、记活动、记作答
  • 表达者：把结果变成孩子听得懂、愿意继续的话
  • 边界守护者：超纲、空内容、证据不足时诚实降级

它不是

  • 内容权威本身（不能随口定义「官方知识点」）
  • 掌握结论的随意宣布者（无作答却说「你已掌握」）
  • 家长职责的替代者（不能让监护者无法看见与纠正）
  • 仅刷题机器或仅闲聊机器人

2.2 功能域总览

由过程模型可自然得到六组功能。组与组之间有依赖，但职责不合并。

F1 · 情境对齐

对应过程 B/C 的入口：弄清「现在学的是哪一科、哪一单元、是否超年级」。

能力要点：识别学科/单元意图；确认歧义；拒绝或改写超纲请求；切换学习情境并告知孩子「我们现在学的是……」。

F2 · 教学讲解

对应过程 B：基于讲解材料 / 教案进行可中断、可追问的教学。

能力要点：按知识点取教学材料；分步讲、举例、检查理解；材料不足时承认局限；教学结束后形成「听讲」类学习活动。

F3 · 练习与检验

对应过程 C：完整的「出题—作答—评判—沉淀」闭环。

能力要点：按情境选题；呈现题目；接收作答；形成作答记录；更新掌握判断；同步「练习」活动。无题时的诚实降级与替代路径，属于本功能的一部分，而不是失败时的随意发挥。

F4 · 真实任务接入

对应过程 D：把作业照片、口头真实题等接入同一套对象，而不是另起炉灶。

能力要点：理解题目；按用户意图分流为「只讲解」或「记入掌握」；低把握时请求家长确认；确认后与 F3 使用同一套作答 / 掌握对象。

F5 · 进度与掌握的陈述

对应过程 E 在对话侧的投影：回答「今天学了什么」「哪里还不熟」。

能力要点：区分进度陈述与掌握陈述；掌握相关表述必须能指向证据；禁止用聊天总结冒充掌握结论。

F6 · 陪伴与安全边界

对应画像与监护底线：让过程可持续、可接受。

能力要点：适龄语气与称呼；情绪承接；拒绝代写等不当请求；在学习主线与闲聊之间保持可拉回。

2.3 功能与过程、对象的映射

Agent 功能 服务的过程 主要读写的对象 对家长的意义
F1 情境对齐 B / C 入口 学习情境、单元 知道孩子「在学哪一块」
F2 教学讲解 B 知识点、教案、学习活动 进度中出现「听讲」
F3 练习与检验 C 习题、作答、掌握判断、学习活动 掌握学情可更新
F4 真实任务接入 D 同上 + 待确认项 作业进入同一套档案
F5 进度与掌握陈述 E（对话侧） 活动、作答、掌握判断 亲子看到同一事实
F6 陪伴与安全 全程 画像（读为主） 可持续、可放心

家长侧的「查看—订正—补内容」可以是独立界面能力，不必须全部由对话 Agent 完成；但 Agent 不得产出与家长侧对象不一致的「影子结论」。

2.4 意图到功能的编排纪律

对话是入口，不是可以省略对象写入的借口。建议用下表约束编排（讨论用）：

学生意图（例子） 应激活的功能 必须留下的对象 明确禁止
想学某单元 F1 → F2 情境 + 听讲活动 把「讲过」写成「已掌握」
出题考考我 F1（若需）→ F3 作答 + 掌握更新 + 练习活动 口头出题判分却不留作答
这题我不会 F2（+ 必要时 F5） 讲解；若涉及「你常错」须有掌握证据 无证据的标签式批评
看看这张作业 F4（再进 F2 或 F3） 按意图：活动 和/或 作答/待确认 不经确认就把不确定结果写成掌握
我今天学了什么 F5 只读活动与作答 用当场编造的总结代替账本

2.5 与「内容建设」的关系

过程 A（内容建设）通常不是学生对话 Agent 的主责，但 Agent 必须感知内容是否就绪：

  • 有知识点、有讲解 → 可教；
  • 有习题 → 可检验；
  • 缺一则降级说明，并指向家长/教研补齐——这本身是 F3/F2 的合格行为，不是产品失败。

因此：教育 Agent 功能设计与内容运营是两条腿；模型上分开，产品节奏上可以并行。

2.6 功能完备性的判据

判断「Agent 功能是否设计合理」，建议用过程能否跑通来检验，而不是用功能点数量：

  1. 学生能否在对话中完成「学新知」并留下进度？
  2. 学生能否完成「练习」并留下掌握证据？
  3. 无内容时，系统是否诚实且仍给出下一步？
  4. 家长能否看见与对话一致的进度与掌握，并纠正错误结论？
  5. 真实作业能否进入同一套对象，而不是旁路消失？

五条皆「是」，则六组功能在原则上闭环；任一长期为「否」，应回到第一部分改模型或补功能，而不是只改话术。

第三部分 · 请一起拍板的问题

下列问题直接影响模型是否成立，建议在进入详细产品方案前形成书面共识。

  1. 是否采纳「学习进度」与「掌握学情」二分？ 若否，请给出替代的家长可见结构，并说明如何避免「听过 = 学会」的混淆。
  2. 「学习活动」是否作为一等对象写入模型？ 若否，家长如何可靠回答「今天学了什么」？
  3. 无题库时，是否允许 Agent 自编题并影响掌握判断？ 建议选项：禁止影响掌握 / 只记活动不记掌握 / 作为「真实题」记入但强标记来源。
  4. 详细教案与讲解点：同一材料加深，还是两套对象？ 影响教研负担与「怎么教」的质量上限。
  5. 知识点变更是否一律需人审？ 影响内容权威与家庭自助扩展速度。
  6. 教育 Agent 的主定位：更偏「过程调度 + 讲解」还是更偏「高强度替代家教」？ 二者都需要 F2，但内容深度与责任边界不同。
  7. 学生过程数据的默认主权：是否以家庭本地为权威，内容包可外部分发？ 属产品伦理与部署假设，宜与模型一并声明。
收束：先承认学习是「内容—过程—证据—监护」的结构，再让 Agent 成为结构中的调度者与讲解者。功能清单 F1–F6 都从这一结构长出来；讨论功能时，请随时指回对应的对象与过程。
