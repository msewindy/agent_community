# 排障速查

来源：<https://huggingface.co/docs/reachy_mini/troubleshooting>  
电机、球形关节、麦克风排线有独立长文，这里只留和 Wireless 开发相关的判断。

官方反复强调的第一步：把机器人和电脑都更新到当前版本，机器人关机，等 5 秒，再开机。Wireless 再跑一次 `reachyminios_check`。

## 连接

| 现象 | 处理 |
|------|------|
| 用 USB-C 插电脑却控制不了 | Wireless 不通过 USB 暴露机器人。用 Wi-Fi 上的 SDK，或 SSH 到机内跑代码。要有线时用 USB-C 转以太网 |
| 看不到 `reachy-mini-ap` | 头部开关必须在 DEBUG，不能在 DOWNLOAD。仍没有就考虑刷镜像 |
| `reachy-mini.local` 无法解析 | mDNS。到路由器 DHCP 表查 IP，或用 Reachy Mini Control 发现。最后才扫网段里谁在 `:8000/api/daemon/status` 应答 |
| 酒店 / 会议 Wi-Fi 上两边都有 IP 但互相访问不了 | 客户端隔离。两边改连手机热点，或 USB-C 转以太网直连 |
| 需要重做热点 | 蓝牙控制台发 `CMD_HOTSPOT`（先 PIN）。见 [07-维护重置与刷机.md](07-维护重置与刷机.md) |
| 网页 App 连不上 | 桌面控制台里这台机器人要登录到你的 HF 账号；同时只能有一个 Web 会话 |

扫网段（把前缀换成自己的局域网）：

```bash
for i in $(seq 1 254); do
  curl -sf --connect-timeout 0.3 "http://192.168.1.${i}:8000/api/daemon/status" >/dev/null 2>&1 && echo "Found: 192.168.1.${i}"
done
```

## 国内网络

- Hugging Face 可设镜像：`export HF_ENDPOINT=https://hf-mirror.com/`。PyPI、GitHub 也可能要镜像。
- 官方对话应用依赖 OpenAI gpt-realtime，在国内经常不可达。变通是在机器人上（或路由器上）开 VPN，并放行局域网，否则你会把自己锁在外面。
- 建议放行：局域网网段，以及端口 22（SSH）、8000（daemon）、5353 TCP/UDP（mDNS）。能做分流时，只让 `huggingface.co` 和 `api.openai.com` 走 VPN。
- VPN 配好后：`sudo systemctl restart reachy-mini-daemon`，再用 `ping reachy-mini.local` 从另一台设备确认。

搜索引擎摘录的官方 FAQ 还提到：Wireless 的 HTTP(S) 代理必须写进 **daemon 服务**，而不只是当前 shell，用 `sudo systemctl edit reachy-mini-daemon` 设置 `HTTP_PROXY` / `HTTPS_PROXY` 后重启服务。本地的 `reachy-mini.local` 不要走代理。以你打开的 FAQ 页面当时条文为准。

## 电机

- 红灯闪、Overload、找不到电机：走 Motors Diagnosis，并用 Reachy Mini Testbench。
- Electrical shock：查供电或短路，尤其是红黑电源线和各段 Dynamixel 三芯线。
- `Input Voltage Error`：官方说明 Reachy Mini 工作电压高于舵机默认值，这条警告是预期的。
- 天线在竖直 0° 抖动：齿轮间隙导致的不稳定平衡。偏开大约 10° 即可，现版本默认已这么做。仍抖可把电机 10、17、18 的 P 降到 180，或把 D 加到 10。
- 头部运动尖啸、连杆附近有黑灰：球形关节需要清洁并重新上脂，见 Spherical Joints Maintenance。

Wireless 上扫描电机：

```bash
ssh pollen@reachy-mini.local
source /venvs/mini_daemon/bin/activate
python -m reachy_mini.tools.scan_motors --wireless
```

电机必须已上电。应看到 ID `10, 11, 12, 13, 14, 15, 17, 18`，波特率 1000000。缺 ID 先查线；出现别的 ID 或波特率再联系支持。

## 音频与对话应用

- 录音是静音或全 0：麦克风 FPC 可能插反或损坏。白蓝线蓝面朝上；黑线有 “Main Board” 字样的一面朝上。仍不行就换排线。
- 没有输入：固件至少 2.1.3。没有声源方向：至少 2.1.0。
- 音量低：软件 ≥ 1.2.3，固件 ≥ 2.1.4。
- 声音发闷：daemon 已有默认均衡，可改 `speaker_eq_gains`。见 [06-相机麦克风与IMU.md](06-相机麦克风与IMU.md)。
- 更新后对话应用一启动就退出，日志停在 `prompts.py` 的 `SystemExit: 1`：旧的自定义 profile 路径失效。先在控制台重置 apps 环境再重装。进阶做法是删掉 `/venvs/apps_venv` 后重装对话应用（已装的其它 App 也会没掉）。

## 应用与 daemon

| 现象 | 处理 |
|------|------|
| App 静默起不来 | 在 `/venvs/apps_venv` 里手动 import，多半是缺依赖 |
| `An app is already running` | `POST /api/apps/stop-current-app` |
| daemon 状态异常 | `sudo systemctl restart reachy-mini-daemon`，等约 30 秒 |
| 改了代码没生效 | 重启 App；手动部署时删 `__pycache__` |
| 日志在哪 | `sudo journalctl -u reachy-mini-daemon -f` |

权限类错误：官方建议先升到 1.2.3 或更新再重启。Windows 上从 HF 装 App 失败，有时是符号链接权限，可设 `HF_HUB_DISABLE_SYMLINKS_WARNING=1`。更早的 SDK 还有 Space 安装 bug，先 `pip install -U reachy-mini`。
