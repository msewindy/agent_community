# 开发工作流

来源：

- <https://huggingface.co/docs/reachy_mini/platforms/reachy_mini/development_workflow>
- <https://huggingface.co/docs/reachy_mini/platforms/reachy_mini/install_daemon_from_branch>

Wireless 的代码最终跑在 CM4 上。官方推荐：仓库放在机器人里，用自己的电脑编辑。

## 前提

- `ssh pollen@reachy-mini.local`（密码 `root`）。
- 知道 IP：控制台、路由器，或 SSH 进去后看 `ifconfig`。`reachy-mini.local` 靠 mDNS，酒店和公司网经常解析失败，这时直接用 IP。
- 应用装在 `/venvs/apps_venv/`，Python 3.12。
- 系统 daemon 装在 `/venvs/mini_daemon/`。

## 跨平台的两种轻量做法

**VS Code Remote - SSH**（Windows、macOS、Linux 都可以）：连 `pollen@reachy-mini.local`，直接打开机器人上的文件夹，保存即写到机内。

**rsync**：每次改完把包同步进 site-packages。

```bash
rsync -avz /path/to/your_app/src/your_app/ \
    pollen@reachy-mini.local:/venvs/apps_venv/lib/python3.12/site-packages/your_app/
```

`--delete` 会删掉机器人上本地已经不存在的文件。

## 做法 A：克隆到机器人，再挂到电脑（官方推荐）

代码放在机器人磁盘上，编辑体验在你自己的 IDE。

```bash
ssh pollen@reachy-mini.local
cd /home/pollen
git clone https://github.com/YOUR_USER/YOUR_APP.git
```

电脑上（Linux 需 `sshfs`）：

```bash
mkdir -p ~/wireless_dev
sshfs pollen@reachy-mini.local:/home/pollen/YOUR_APP ~/wireless_dev \
    -o reconnect,ServerAliveInterval=15,ServerAliveCountMax=3
```

机器人上安装并运行：

```bash
cd /home/pollen/YOUR_APP
/venvs/apps_venv/bin/pip install -e .
/venvs/apps_venv/bin/python -m YOUR_MODULE.main
# 或不安装，直接：
/venvs/apps_venv/bin/python your_script.py
```

卸载挂载：`fusermount -u ~/wireless_dev`。

Windows 没有现成的 `sshfs` / `fusermount`。同一目标用 VS Code Remote-SSH，或在 WSL 里挂载。

## 做法 B：盖住已经装好的 App

App 已经从控制台装进：

```text
/venvs/apps_venv/lib/python3.12/site-packages/YOUR_APP_NAME/
```

在**机器人上**把电脑里的包目录挂过来（只挂 `src/your_app/` 里面那层，不要挂整个 git 仓库）：

```bash
sshfs YOUR_USER@YOUR_PC_IP:/path/to/your_app/src/your_app \
    /venvs/apps_venv/lib/python3.12/site-packages/YOUR_APP_NAME \
    -o reconnect,ServerAliveInterval=15,ServerAliveCountMax=3
```

仓库是 `your_app/src/your_app/__init__.py`，site-packages 里直接就是 `your_app/__init__.py`。挂错一层，Python 找不到模块。

## 做法 C：挂上源码直接跑

不经过 pip，也不在控制台里注册。适合临时试，控制台里看不到这个 App。

```bash
mkdir -p /home/pollen/my_app_mount
sshfs YOUR_USER@YOUR_PC_IP:/path/to/your_app /home/pollen/my_app_mount \
    -o reconnect,ServerAliveInterval=15,ServerAliveCountMax=3
cd /home/pollen/my_app_mount
/venvs/apps_venv/bin/python main.py
```

## 不要踩的点

- 把电脑目录挂到机器人上再 `pip install`，会非常慢（大量小文件走网络）。用做法 A，或跳过安装直接 `python -m`。
- 从控制台安装的 App，改的是 site-packages 里的包内容，不是仓库根目录。

指定分支装进应用环境：

```bash
/venvs/apps_venv/bin/python -m pip install --force-reinstall \
    "git+https://github.com/pollen-robotics/MY_AWESOME_APP.git@MY_AWESOME_BRANCH"
```

分支名、tag、commit 都可以。

## 常用命令

| 动作 | 命令 |
|------|------|
| SSH | `ssh pollen@reachy-mini.local` |
| 停 daemon | `sudo systemctl stop reachy-mini-daemon` |
| 启 daemon | `sudo systemctl start reachy-mini-daemon` |
| 看日志 | `journalctl -u reachy-mini-daemon -f` |
| 自检 | `reachyminios_check` |

## 用未发布分支替换 daemon

只给开发和测试用。分两种。

**本机试验（不动系统安装）**

```bash
ssh pollen@reachy-mini.local
git clone -b <branch-name> https://github.com/pollen-robotics/reachy_mini.git
cd reachy_mini
uv venv --python /venvs/mini_daemon/bin/python .venv
source .venv/bin/activate
uv sync --extra gstreamer --extra wireless-version
sudo systemctl stop reachy-mini-daemon
reachy-mini-daemon --wireless-version
```

重启后系统服务会自己起来，所以每次重启都要再停一次系统 daemon。这个模式不要拿去装 App，本地改过的 `reachy_mini` 传不到 App 环境。

**装成系统 daemon（可以配合控制台装 App）**

```bash
source /venvs/mini_daemon/bin/activate
pip install --no-cache-dir --force-reinstall \
  "reachy_mini[gstreamer,wireless-version] @ git+https://github.com/pollen-robotics/reachy_mini.git@<branch-name>"
sudo systemctl restart reachy-mini-daemon
pip show reachy-mini | grep Version
```

这里必须用 `pip`，不能用 `uv pip`：`uv` 对 git LFS 的处理和这个安装方式不兼容。版本 ≤ 1.2.13 时，还要对 `/venvs/apps_venv` 重复安装一次。

回退：用蓝牙发 `SOFTWARE_RESET`，重装出厂 daemon，见 [07-维护重置与刷机.md](07-维护重置与刷机.md)。日志：`journalctl -u reachy-mini-daemon -f`。
