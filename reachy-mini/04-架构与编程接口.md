## 客户端 / 服务端

1. **Daemon（服务端）** 跑在 Wireless 的 CM4 上。它做硬件 IO、安全限位、读传感器，并在 `http://reachy-mini.local:8000` 提供 REST 和 WebSocket。
2. **SDK（客户端）** 是 `reachy_mini` 包，或浏览器里的 JS SDK。AI 代码可以放在更强的机器上，daemon 留在机器人上。

Python 安装（电脑侧，控制远程机器人或写 App）：Python 3.10–3.12，官方推荐 3.12，并用 `uv`。

```bash
uv venv reachy_mini_env --python 3.12
uv pip install "reachy-mini"
```

仿真额外加 `reachy-mini[mujoco]`。从源码改 SDK 时克隆 <https://github.com/pollen-robotics/reachy_mini> 后 `uv sync`。Linux 上还要单独装 GStreamer；USB 的 udev 规则是给 Lite 用的，Wireless 远程控制不靠那条 USB。

## 坐标系与限位

- **Head frame**：头底部，给 `goto_target` / `set_target`。
- **World frame**：相对底座固定，给 `look_at_world`。

SDK 会把超出范围的指令夹到最近的合法位姿。两处官方页面的身体偏航范围不一致，写控制时以你机器人上的 daemon 实际夹取为准：

| 轴 | Core Concepts | Troubleshooting FAQ |
|----|---------------|---------------------|
| Head Pitch / Roll | [-40°, +40°] | 同左 |
| Head Yaw | [-180°, +180°] | 同左 |
| Body Yaw | [-160°, +160°] | [-180°, +180°] |
| Head 与 Body 的 Yaw 差 | 最大 65° | [-65°, +65°] |

电机模式：

- `enable_motors()`：锁住，保持位置。
- `disable_motors()`：卸力。
- `enable_gravity_compensation()`：软保持，可以用手摆头，松手停在当前位置。只在 Placo 运动学后端下可用。排障里的 `make_motors_compliant()` 是同一类「电机开着但软」的示教模式。

## Python 运动

`goto_target` 做平滑插值，可同时给 `head`、`antennas`、`body_yaw`。插值：`linear`、`minjerk`（默认）、`ease_in_out`、`cartoon`。

```python
from reachy_mini import ReachyMini
from reachy_mini.utils import create_head_pose
import numpy as np

with ReachyMini() as mini:
    mini.goto_target(
        head=create_head_pose(z=10, mm=True),
        antennas=np.deg2rad([45, 45]),
        body_yaw=np.deg2rad(30),
        duration=2.0,
        method="minjerk",
    )
```

`set_target` 不做插值，给手柄或自生成轨迹这种高频控制。示教回放用 `start_recording()` / `stop_recording()`。

看向：

- 图像坐标 `look_at_image(x, y)`，左上角是 (0, 0)。
- 世界坐标 `look_at_world(x, y, z)`。

头部人脸跟踪在 daemon 内完成，对准最近的脸的鼻子：

```python
mini.start_head_tracking()          # weight=1.0 跟踪占满头部；0.0 暂停检测
face = mini.get_tracked_face()      # detected, x, y ∈ [-1, 1], roll
mini.stop_head_tracking()
```

## REST 与 WebSocket

交互文档：<http://reachy-mini.local:8000/docs>  
OpenAPI 原文：<https://raw.githubusercontent.com/pollen-robotics/reachy_mini/main/docs/source/API/openapi.json>

| 类别 | 前缀 | 作用 |
|------|------|------|
| Apps | `/api/apps` | 列出、安装、启动、停止 |
| Daemon | `/api/daemon` | 启停、重启、状态 |
| State | `/api/state` | 头部位姿、身体偏航、天线、声源方向 |
| Move | `/api/move` | goto、set target、播放录制动作 |
| Motors | `/api/motors` | 电机状态、控制模式 |
| Kinematics | `/api/kinematics` | IK、URDF、STL |
| Volume | `/api/volume` | 扬声器与麦克风音量 |
| HF Auth | `/api/hf-auth` | Hugging Face token |

常用状态：

- `GET /api/state/full`
- `ws://reachy-mini.local:8000/api/state/ws/full`

官方把这套 API 当成接非 Python 控制器、生成客户端、甚至做 MCP 服务的接口。

## JavaScript / WebRTC

包：`@pollen-robotics/reachy-mini-sdk`。做可分享应用时，官方要求先读仓库里的 `ts/APP_CREATION_GUIDE.md`，并把 SDK 钉在文档当时验证过的版本（笔记拉取时写的是 `@pollen-robotics/reachy-mini-sdk@1.8.0`，以指南为准）。

路径：

1. 静态页面（通常是 Hugging Face Space）。
2. 信令走 HF Space 上的中心服务器（默认 `https://pollen-robotics-reachy-mini-central.hf.space`）：OAuth、列出你能连的机器人、交换 SDP/ICE。
3. 媒体和指令随后是浏览器与机器人之间的 **WebRTC 直连**。视频 H.264，音频 Opus。信令服务器不再在媒体路径上。

状态：`disconnected` → `connect()` → `connected` → `startSession()` → `streaming`。不用 host shell 时，`autoConnect()` 会串起登录、选机器人、开会话、`ensureAwake()`。

Host shell（`mountHost()` / `connectToHost()`）负责登录、选机器人和顶栏，用户页面跑在 iframe 里。Reachy Mini Control 和 Spaces 应用都走这条路。

## 唤醒与休眠：应用不要自己管

官方契约是：**平台负责醒和睡，应用只清理自己的资源。**

- 会话建立时客户端调用 `ensureAwake()`，应用看到的机器人已经在位置控制下。
- 正常离开时，编排会话的那一侧在断线前让机器人睡下。
- 崩溃、关标签、Wi-Fi 掉线时，daemon 的 idle reset 把机器人从任意电机状态收回。
- 协调条件是：电机 `Disabled` 且已经在睡眠位姿。干净离开满足它，idle reset 就不再补一次动作。

Wireless 上可以让 daemon 起来先不唤醒，并在唤醒或摸天线后启动某个已安装 App：

```bash
reachy-mini-daemon --wireless-version --no-wake-up-on-start --startup-app reachy_mini_conversation_app
```

`--startup-app` 本身就是「摸天线也启动这个 App」的开关。已经有本地 App 或远程会话时不会抢占。
